# AI백과사전 원고 작성 (Claude → 슬랙 ✅ → 발행)

원고는 Claude 가 쓴다. 구글 AI(Gemini) API 는 쓰지 않는다 (비용 0원). 발행은 사용자가 슬랙 원고 메시지에 ✅ 를 눌러야만 된다.
**Claude 는 절대 ✅ 를 누르거나 직접 발행하지 않는다** — 승인은 사용자의 몫이다.

## 카테고리 (블로그 메뉴 순서)
AI 언어 모델 · AI 도구 · AI 논문 분석 · AI 뉴스 리뷰 · AI 보안 · AI 인사이트 · AI 공모주 분석
"카테고리별로" / "전체" 요청이면 이 순서로 1편씩, 앞에서 고른 주제와 겹치지 않게 쓴다.

## 순서 (1편마다)
1. **지침 보기 + 원고 폴더 만들기**
   ```bash
   python scripts/claude_brief.py --category "AI 보안" --new
   ```
   출력의 글 문법·사실 규칙·post.json/research.json 형식·**이미 쓴 글 목록**을 그대로 따른다. 마지막 줄이 원고 폴더 경로.
2. **주제 고르기**: WebSearch 로 최근(보통 3일, 논문·보안·공모주는 14일) 공식 발표·1차 자료가 있는 AI 소식. 이미 쓴 글과 같은 주제·같은 원문 금지.
   - 공모주: 증권신고서·공시·공식 보도자료만. 수익 전망·매수 권유 금지 (안내문은 시스템이 붙인다).
3. **조사**: WebFetch 로 공식 발표·문서·논문 원문을 직접 읽고, 신뢰할 수 있는 언론으로 교차 확인. 출처 4~10개, 출처 url 은 실제로 읽은 원래 주소.
   인용 이미지가 설명을 도우면 이미지가 실린 **출처 페이지**를 최대 3개 images 에 (파일 주소를 모르면 image_url 은 빈 문자열).
4. **원고 (post.json)**: 지침의 OUTPUT_SCHEMA 그대로. 참고 블로그 문법(이모지 제목, "안녕하세요!" 도입, 한눈에 보기, 이모지 h2, 💡/⚠️ 박스, 표, FAQ, 맺음말 끝인사),
   문단마다 핵심 1~3곳 `**형광 강조**`, 관련 문단 뒤 `{"type": "image", "image_id": "I1"}`. 본문 공백 제외 5,000자 이상.
   발표일은 출처에 적힌 날짜만 (오늘 날짜를 발표일처럼 쓰지 않는다). `category` 는 요청 카테고리 그대로.
5. **사실 검증**: 원고의 수치·날짜·이름·가격·스펙 주장을 모두 뽑아, 원고와 별개로 출처를 다시 열어 하나씩 확인.
   틀린 것은 고치고, 확인되지 않는 문장은 뺀다 (같은 내용이 도입·요약·표·FAQ 에 반복되면 모두).
   결과를 research.json 의 `factcheck` 에: `{"claims": 전체 주장 수, "confirmed": 확인 수, "removed": [뺀 문장], "note": "방법"}`.
6. **원고 폴더에 저장**: `post.json`, `research.json` (UTF-8).
7. **준비·슬랙 승인 요청**
   ```bash
   python scripts/claude_draft.py output/claude_drafts/<ID>             # 슬랙 원고 채널에 '✅ 누르면 발행' 메시지
   python scripts/claude_draft.py output/claude_drafts/<ID> --no-send   # 미리보기만 (확인용)
   ```
   출처가 열리지 않거나(404), 인용 이미지가 확인을 통과하지 못하면 자동으로 빼고 '참고'에 표시된다.
   "이미 발행한 주제와 겹칩니다" 가 나오면 다른 주제로 다시 쓴다.
8. 사용자에게 제목·카테고리·사실 검증 결과·슬랙 메시지 위치를 보고하고, **✅ 는 사용자가 누르도록** 안내한다.

## 발행 이후 (자동)
슬랙 ✅ → Cloudflare Worker(`/slack/events`) → GitHub Actions `publish_draft.yml` → 구글 블로그 발행 → 원고 메시지 스레드에 결과.
실패하면 스레드에 '다시 누르면 재시도' 가 남고, ✅ 를 다시 누르면 다시 시도한다. 이미 발행한 원고는 두 번 올라가지 않는다.
